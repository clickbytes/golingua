# Request-scoped world facts

`internal/facts` stores explicit assertions about individual referents for one request. A `ConceptDefinition` describes a class or relation in CORE; it does not assert that two individuals are related. A `MeaningGraph` describes an interpretation of an utterance; it is not persistent world knowledge. There is no session memory in Go v0.

`NewSet` requires a pinned CORE graph, a validated request context with distinct referent IDs and entity/abstract concept types, and explicit binary relation facts. The relation ID must exist in CORE. Its subject/object kind signatures constrain the two referents. Each fact has a stable request-local ID, positive or negative polarity, asserted scope, source evidence, and an optional UTC validity interval. Document sources require a `provenance.SourceRef`; metadata records provenance but does not approve the claim.

The set copies its inputs and outputs. No package-global state or storage is used. Both polarities remain available through `EvidenceFor`; no match means **unknown**, not false. Two opposite assertions are both retained with their evidence. Later query logic must consider validity time and report conflict when both apply. This first contract does not infer event facts from concept taxonomy, typical edges, lexical senses, or missing information.

Only an explicit statement can be considered for a later mapping from `MeaningGraph` to facts. `AssertedMeaning` checks CORE roles and the asserted projection, rejecting the whole input if any question, negative, hypothetical, modal, quantified, or nonassertive content remains. It does not perform the mapping: a later caller must provide an explicit mapping from an asserted event/state concept and its participants to a declared relation and known referent identities. A scoped negation is never imported as a positive fact. To assert a negative relation, the request must supply a fact with `negative` polarity and explicit evidence.

Bounds are 4096 facts and 4096 referents per request, with lower caller budgets allowed. The current package covers binary CORE relations; event/role predicates need a separate declared signature before they can enter a FactSet. The CLI does not yet accept FactSet or answer questions; G06-02 through G06-05 build on this library boundary. Manual question/answer evaluation stays `NOT RUN` until owner inputs and a working CLI path exist.
