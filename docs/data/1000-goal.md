# CORE inventory target

The catalog aims for approximately 1000 distinct, described CORE concepts.
`catalog.Count()` compiles the Go declarations and counts only the resulting
`ConceptDefinition` records. It does not count lexical senses, surface words,
inflected forms, synonyms or example sentences. The target is an editorial
size goal and does not gate CI or certify translation quality.

On main after G07 #59–#61 the first batch contains **49/1000** CORE concepts.
The independent PL lexicon has 16 lexemes and 20 senses; EN has 19 lexemes and
28 senses. `catalog.Inspect()` reports per-concept status from the supplied
compiled indexes. There are 16 PL and 19 EN concepts with at least one pending
candidate, 33 without a PL candidate and 30 without an EN candidate. There are
**zero approved concepts and zero approved PL+EN pairs**. These are inventory
counts, not coverage or accuracy percentages.

`pending` means that a language-local `SemanticBinding` exists but cannot
authorize transfer. `approved` requires an exact approved equivalent binding
with valid provenance; `absent` means there is no binding in that language's
index for the concept. `non_transferable` records an existing approved
non-equivalent binding without treating it as a translation license. An
approved pair would require approved equivalent bindings in
both language indexes. The report never promotes candidates automatically.

Further editorial work must write distinct concept definitions rather than
filling the target with extra labels. New language records may have multiple
senses per lemma and multiple lemmas per concept. They must be counted
separately from CORE. Manual translation review remains NOT RUN until the
owner supplies inputs and evaluates the actual CLI output.
